# 技能文档格式

一个 `.md` 文件就是一份技能。放在 `<skillDir>` 下，扩展启动时扫描。

## 最小写法

```markdown
# 泡茶

先烧水，水温 85 度左右。绿茶别用沸水。
```

文件名 `泡茶.md` 会变成技能名，正文第一行引用块（如果有）会变成触发条件。没有 frontmatter 也能用。

## 推荐写法

```markdown
---
name: 泡茶
when: 用户说想喝茶、问怎么泡茶的时候
---

# 泡茶

## 先问什么
...

## 步骤
...
```

### name

显示名，会进索引。不写就用文件名。

**控制在 6 个字以内**——它进索引，索引每轮都在上下文里。

### when

一句话说明什么情况下该用。这一段直接进索引，是桌宠判断「要不要读这份」的唯一依据。

写法要点：

- 写**触发场景**，不写功能描述。「用户说想喝茶」比「关于泡茶的说明」有用得多
- 一句话说完，不要分段
- 字数控制在 30 字内。索引是常驻的，每份多 10 个字，十份就是 100 个字

## 正文

正文不进索引，只在 `skill_read` 时读进对话。所以可以写长，但也要克制——写太长的技能，读一次就吃掉几千 token。

建议结构：

```markdown
## 什么时候用
（边界情况，比 when 更细）

## 怎么做
（步骤）

## 注意
（容易搞错的地方）
```

## 索引成本怎么算

每份技能在上下文里占的字数 ≈ `name` + `when` + 3 个字符（分隔符）。

参考值：

| 技能数 | 索引字符 |
|---|---|
| 2 | 68 |
| 5 | ~170 |
| 10 | ~340 |
| 20 | ~680 |

二十份技能的索引还不到 700 字符，比一段普通提示词还短。但正文不占，所以**技能数量不是瓶颈，when 写多长才是**。

## 命名

文件名可以中文，可以带空格。`skill_read` 按名字或文件名都能找到。

同一个名字不要重复，重复时按文件名排序取第一个。

## 增删改

直接改文件就行，扩展用目录 mtime 判断要不要重建索引，不需要重启。

改完索引会在下一次前缀重建时更新（跟她的下一轮对话）。
